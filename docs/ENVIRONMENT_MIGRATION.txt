四、从本 TXT 提取可安装清单与激活脚本
------------------------------------
在本 TXT 所在目录运行以下命令（使用系统 Python 3 或 Conda base 的 Python 3）：

python3 - <<'PY'
from pathlib import Path
text = Path('HyperSynergyV3_environment.txt').read_text(encoding='utf-8')
blocks = {
    'CONDA_EXPLICIT': 'conda-explicit-v3.txt',
    'PIP_ONLY': 'pip-only-v3.txt',
    'CUDA_ACTIVATE': 'hyper-cuda-activate.sh',
    'CUDA_DEACTIVATE': 'hyper-cuda-deactivate.sh',
    'CONDA_PINNED': 'conda-pinned-v3.txt',
}
lines = text.splitlines()
for name, filename in blocks.items():
    begin = lines.index('# BEGIN ' + name)
    end = lines.index('# END ' + name, begin + 1)
    Path(filename).write_text('\n'.join(lines[begin+1:end]) + '\n', encoding='utf-8')
    print('Wrote', filename)
PY

说明：执行上面代码时，write_text 内应为 Python 换行转义 '\n'。

五、目标机重建顺序（联网方案）
------------------------------
前提：目标机使用 Linux x86_64，已安装并初始化 Conda；在上述提取文件所在目录执行。
环境名 hyper_v3 用于新建，不覆盖已有 hyper 环境。

conda create -n hyper_v3 --file conda-explicit-v3.txt
conda activate hyper_v3
python --version

先恢复环境专用 CUDA 动态库搜索路径与版本固定文件：

mkdir -p "$CONDA_PREFIX/etc/conda/activate.d" "$CONDA_PREFIX/etc/conda/deactivate.d"
cp hyper-cuda-activate.sh "$CONDA_PREFIX/etc/conda/activate.d/hyper-cuda.sh"
cp hyper-cuda-deactivate.sh "$CONDA_PREFIX/etc/conda/deactivate.d/hyper-cuda.sh"
cp conda-pinned-v3.txt "$CONDA_PREFIX/conda-meta/pinned"
conda deactivate
conda activate hyper_v3

再安装 PyTorch CUDA 11.0 版本：

python -m pip install --no-deps 'torch==1.7.0+cu110' -f https://download.pytorch.org/whl/torch_stable.html

安装从源机器复制过来的四个 PyG CUDA wheel（替换下面的实际路径）：

WHEELS=/迁移目录/v3-wheels
python -m pip install --no-deps --no-index --only-binary=:all: --find-links "$WHEELS" 'torch-scatter==2.0.5' 'torch-sparse==0.6.8' 'torch-cluster==1.5.8' 'torch-spline-conv==1.2.0'

最后安装 pip 完整分组；已安装的同版本 torch/CUDA 扩展保持满足要求：

python -m pip install --no-deps --find-links "$WHEELS" -r pip-only-v3.txt
python -m pip check

这里 --no-deps 配合“完整 Conda 清单 + 完整 pip 分组”使用，不是省略依赖。
安装后必须以 pip check 和算子验证确认，没有通过不能开始正式训练。
本文未联网测试旧包下载链接当前是否可用；若下载失败，保留指定版本并取得对应原包。
如 pytorchtools==0.0.2 的索引解析失败，可使用本文附录记录的实际安装来源 URL。
不要将最后的原始 pip freeze 区块直接用于重建：它含源机器 wheel 路径及 Conda 构建路径。
PIP_ONLY 区块已按当前安装元数据写成 name==version，避免把这些机器路径带进安装命令。

六、V3 运行配置及路径迁移
------------------------
V3 BioGraph 的入口是 experiments/innovation_1_biograph/run_stage.py。
根目录 run_v2_training.sh 是保留的 V2 启动器，且 Python 路径写死为原机器路径。
BioGraph 应使用上面的 V3 分阶段入口，并保留其中禁用 GPU JIT fusion 的三行：

    torch._C._jit_override_can_fuse_on_gpu(False)
    torch._C._jit_set_texpr_fuser_enabled(False)
    torch._C._jit_set_nvfuser_enabled(False)

这三行已存在于 V3 run_stage.py，直接使用入口会自动应用。
代码中有显式 .cuda()；完整元训练/测试需要 CUDA，CPU 导入通过不等于可以 CPU 完整训练。
环境激活钩子将本环境 lib 加入 LD_LIBRARY_PATH，用于解析 libcusparse.so.11 等 CUDA 库。
不要把 NVIDIA 驱动显示的 CUDA 数字当作此 Python 环境实际使用的 CUDA 版本。

推荐运行变量：

export PYTHONDONTWRITEBYTECODE=1
export PYTHONUNBUFFERED=1
export CUDA_VISIBLE_DEVICES=0

GPU 编号 0 是示例，请选择目标机器可用 GPU。
HYPERSYNERGY_ENCODER_CONFIG / HYPERSYNERGY_RUN_DIR / HYPERSYNERGY_TEST_CHECKPOINT
由 run_stage.py 自动设置；新训练使用新的 run 目录。

已经实际使用且本次预检通过的配置：
experiments/innovation_1_biograph/transfer_audit_20261102/results/staged/biological_graph.candidate.json

对应正式运行记录：
experiments/innovation_1_biograph/runs/formal_biograph_stage2_restart_20261105_145123/RUN_RECORD.json
该 RUN_RECORD 明确使用 /data/jyk/miniconda3/envs/hyper/bin/python。

实际 PPI/基因映射文件在：
experiments/innovation_1_biograph/transfer_audit_20261102/results/staged/gene_index.csv
experiments/innovation_1_biograph/transfer_audit_20261102/results/staged/ppi_edges_entrez.csv
experiments/innovation_1_biograph/transfer_audit_20261102/results/staged/ppi_source.json

注意：experiments/innovation_1_biograph/configs/biological_graph.json 仍指向
目前不存在的 data/biological_graph/ppi_edges.csv；不能直接把它当作当前正式训练配置。
迁移应使用已验证的 candidate 配置或相应 run/configs/encoder.json。
这些配置里的 *_path 包含 /data/jyk/HyperSynergyV3 绝对路径。
若目标项目目录不同，需要在迁移副本中把路径指向实际数据位置，并重新做 check-only。
源项目含指向 /data/jyk/HyperSynergyV3 的绝对软链接；部分历史 runs 还指向
/data/jyk/HyperSynergyV2 copy。tar 保留的是软链接本身，不能假设外部链接目标也已打包。
迁移已有 run 时需核对 data/权重软链接；不要把所有历史 V2 权重链接盲目改指 V3 权重。
加载旧 checkpoint 还要通过原严格加载器的配置/图/权重匹配检查。
这些路径问题与 Python 包是否安装成功是两项独立检查。

七、目标机验收命令（先验收，再训练）
----------------------------------
激活 hyper_v3 并设置项目实际位置，先做小型 GPU 算子检查：

nvidia-smi
python -m pip check
python -B - <<'PY'
import sys, torch, torch_geometric
from torch_scatter import scatter_add
from torch_geometric.nn import TransformerConv, GATv2Conv, GlobalAttention
from torch_geometric.nn.norm import GraphNorm
print('Python:', sys.version)
print('Torch:', torch.__version__, 'CUDA:', torch.version.cuda)
print('PyG:', torch_geometric.__version__)
assert torch.__version__ == '1.7.0+cu110'
assert torch_geometric.__version__ == '1.7.2'
assert torch.cuda.is_available(), 'CUDA unavailable'
torch._C._jit_override_can_fuse_on_gpu(False)
torch._C._jit_set_texpr_fuser_enabled(False)
torch._C._jit_set_nvfuser_enabled(False)
print('GPU:', torch.cuda.get_device_name(0))
x = torch.randn(4, 8, device='cuda', requires_grad=True)
edge = torch.tensor([[0, 1, 2, 3], [1, 2, 3, 0]], dtype=torch.long, device='cuda')
for cls in (TransformerConv, GATv2Conv):
    layer = cls(8, 8).cuda()
    y = layer(x, edge)
    assert torch.isfinite(y).all().item()
    y.sum().backward()
z = scatter_add(torch.ones(4, device='cuda'), torch.tensor([0, 0, 1, 1], device='cuda'), dim=0)
assert z.tolist() == [2.0, 2.0]
torch.cuda.synchronize()
print('PASS: CUDA / PyG forward and backward')
PY

然后验证实际 BioGraph 配置；PROJECT 应替换为目标路径，且先修正配置中的绝对路径：

PROJECT=/目标路径/HyperSynergyV3
cd "$PROJECT"
EXP=experiments/innovation_1_biograph
CFG="$EXP/transfer_audit_20261102/results/staged/biological_graph.candidate.json"
python -B "$EXP/run_stage.py" --stage 1 --config "$CFG" --run-dir "$EXP/runs/migration_preflight" --check-only

--check-only 只做预检，不启动训练；上述 GPU 小测试也不能替代真实训练验证。
如需新开完整实验，可用一个不存在的新 run 目录依次执行原三阶段：

RUN="$EXP/runs/migrated_biograph_new"
python -B -u "$EXP/run_stage.py" --stage 1 --config "$CFG" --run-dir "$RUN"
python -B -u "$EXP/run_stage.py" --stage 2 --config "$CFG" --run-dir "$RUN"

Stage 3 还必须用 --checkpoint 指定该 RUN/checkpoints/stage2/ 中实际存在的 checkpoint。
不要直接重跑已完成的训练目录；原入口有防覆盖检查。
